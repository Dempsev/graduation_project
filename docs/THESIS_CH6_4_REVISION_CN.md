# 第 6.4 节修改建议与可替换正文

本文档针对当前 `total (2).pdf` 中第 6.4 节提出修改建议。核心问题是：当前 6.4 的标题和正文强调“带边模态机制”和“真实物理意义”，但本节紧接着展示的是局部精修前后预测覆盖率、评分和候选表。若不插入对应的 COMSOL 频散图/模态图，容易被评委认为“物理解释证据不足”。

## 一、主要问题

### 1. 标题和证据类型不完全匹配

当前标题是：

**6.4 典型案例与带边模态机制分析**

但 6.4 中真正展示的主图是：

**图 6-7 典型案例局部精修前后覆盖率对比**

后续表 6-2(a)(b)(c) 也主要是 `score`、`cover`、`overlap`、`contact prob`、`open prob` 和 `distance`。这些属于预测驱动局部精修的候选质量证据，不是直接的 COMSOL 模态图证据。

因此，如果本节暂时不放真实的带边模态图或频散图，标题建议改为：

**6.4 典型案例的局部精修与候选质量分析**

如果确实要保留“带边模态机制分析”这个标题，则需要在本节中补入至少一张频散图或模态图，并配一段具体读图文字。

### 2. “真实设计能力”和“真实物理机制”表述偏强

当前 6.4 开头写：

> 为验证预测驱动主线的真实设计能力……

但 6.4 的表格主要还是预测器输出和局部精修结果，真正的真实物理验证在 6.7。建议把 6.4 的定位降一级，写成：

> 为考察预测驱动主线是否能够产生稳定且值得进入真实验证的候选结构……

这样更严谨。第 6.4 证明“候选质量和机制线索”，第 6.7 才证明“真实 COMSOL 验证成立”。

### 3. 中英夹杂偏多

当前出现较多英文术语：

- `canonical case`
- `witness case`
- `archetype case`
- `predictor`
- `lower edge`
- `upper edge`
- `dispersion`
- `mode shape`
- `target-band score`
- `cover ratio`
- `overlap`

建议第一次出现时保留英文括注，后文改中文：

| 当前写法 | 建议写法 |
|---|---|
| predictor | 预测器 |
| canonical cases | 典型案例 |
| witness case | 见证案例或物理证据案例 |
| archetype case | 结构原型案例 |
| lower edge / upper edge | 下带边 / 上带边 |
| dispersion | 频散关系 |
| mode shape | 模态振型 |
| target-band score | 目标频带评分 |
| cover ratio | 覆盖率 |
| overlap | 重叠宽度 |

表格列名也建议中文化，例如 `Case ID` 可改为“案例编号”，`Shape ID` 可改为“结构编号”，`Family` 可改为“结构族”，`Base score` / `Best score` 可改为“基准评分” / “精修后评分”。

## 二、推荐结构

建议将 6.4 改成以下结构：

**6.4 典型案例的局部精修与候选质量分析**

- 6.4.1 典型案例选择与分析目的
- 6.4.2 局部精修前后预测指标对比
- 6.4.3 典型案例的物理机制线索

其中 6.4.3 只做“机制线索”总结，不要把真实验证结论提前写满。COMSOL 真实验证结果留到 6.7。

如果想保留 `ep17`、频散图和模态图，建议放到 6.6 或 6.8：

- 6.6：弱频带与形状机制分析，适合放 ep17/bilobe/archetype 这种机制性图。
- 6.8：局部鲁棒性与机制稳定性分析，适合放 canonical local robustness 的频散对照图。

## 三、可直接替换的 6.4 开头正文

建议将当前 6.4 开头替换为：

```text
6.4 典型案例的局部精修与候选质量分析

为考察预测驱动主线是否能够产生稳定且值得进入真实验证的候选结构，本文选取若干典型目标频带案例，对局部精修前后的候选质量进行对比分析。与第四章中单纯评价预测器离线指标不同，本节关注的是：经过候选评分和局部精修后，候选结构是否能够在目标频带评分、预测覆盖率、预测重叠宽度以及接触可行性等方面保持或获得改善，从而具备进入后续真实 COMSOL 验证的价值。

需要说明的是，本节中的评分、覆盖率和重叠宽度主要来自预测器和局部精修阶段的候选评价结果，不能直接等同于最终物理验证结论。它们的作用是说明预测驱动流程能否稳定产生高优先级候选；候选结构是否真正形成可确认的带隙增益，仍需依赖 6.7 节的 Stage4 真实物理验证结果。因此，本节承担的是“候选质量分析”和“机制线索解释”的作用，而不是提前替代真实验证。
```

## 四、可替换 6.4.1 的正文

当前 `6.4.1 Canonical cases 的带边模态分析` 建议改为：

```text
6.4.1 典型案例选择与局部精修结果

本文选取的典型案例覆盖多个目标频带和结构族，既包含相对稳定的中频目标频带，也包含较高频段和弱频带条件下的候选结构。这样设置的目的不是证明所有案例都能获得显著提升，而是检验预测驱动流程在不同目标频带条件下是否能够稳定输出可解释、可验证的候选。

从图 6-7 和表 6-2 可以看出，局部精修后的候选并非在所有案例上都出现大幅提升。前三个案例的目标频带评分、预测覆盖率和预测重叠宽度基本保持不变，而 band180_220_ep248 案例在评分、覆盖率和重叠宽度上获得小幅改善。这一结果说明，当前保守局部精修的主要作用不是无约束地追求大幅数值提升，而是在高分 seed 的邻域内筛选更稳定、更适合进入真实验证的候选。

这种结果也符合本文对局部精修的定位：它是预测驱动流程中的候选推进步骤，而不是全局最优搜索。对于已经具有较高目标频带评分的结构，局部精修可能表现为稳定保持；对于仍存在可改进空间的结构，局部精修则可能带来小幅增益。两类结果共同说明，局部精修在当前目标频带目录内具有候选修正和候选稳健化作用。
```

## 五、可替换 6.4.2 的正文

当前 `6.4.2 ep17 witness case 的物理证据` 不建议放在 6.4，除非本节真的插入 ep17 的频散图和模态图。否则建议改为：

```text
6.4.2 典型案例的物理解释边界

典型案例的评分和覆盖率变化能够说明候选质量是否改善，但还不足以单独证明结构的真实物理机制。对于声子晶体目标频带设计而言，真正的物理解释需要结合频散曲线、上下带边模态振型以及局部场分布共同判断。其中，频散曲线用于确认目标频带附近是否存在带隙或带隙边界，模态振型用于观察带边两侧的振动形态差异，应变能密度和等效应力云图则用于解释局部能量聚集和应力集中位置。

因此，本文将典型案例中的预测评分结果理解为“值得进入物理解释和真实验证的候选线索”，而不是最终物理结论。后续 6.6 节将进一步结合结构原型和局部场分布分析不同形状机制，6.7 节通过 Stage4 真实物理验证确认候选结构是否获得正向带隙增益，6.8 节则从局部扰动和频散关系角度考察部分案例的机制稳定性。
```

如果你坚持保留 ep17 在 6.4，则建议把标题改成：

**6.4.2 ep17 见证案例的频散与模态证据**

并且必须插入对应的频散图或模态图，不能只用文字说 `dispersion` 和 `mode shape`。

## 六、图 6-7 和表 6-2 后的建议解释

当前图 6-7 后的解释方向是对的，但可以更中文、更稳妥。建议替换为：

```text
如图 6-7 所示，典型案例分析首先检验的是同一目标频带条件下局部精修前后的预测覆盖率变化。结果表明，局部精修并未在所有案例中带来显著提升；多数案例主要表现为稳定保持，band180_220_ep248 则出现小幅改善。这说明当前局部精修更适合作为高分候选附近的稳健修正环节，而不宜表述为对所有结构都具有显著提升能力的优化器。

表 6-2(a) 至表 6-2(c) 进一步给出了典型案例的结构身份、预测评分、覆盖率、重叠宽度和可行性指标。前三个案例在保守搜索范围内基本保持原有预测质量，band180_220_ep248 的目标频带评分提高 0.0020，预测覆盖率提高 0.0101，预测重叠宽度提高 0.4023 Hz。虽然这些提升幅度不大，但它们发生在距离 seed 较小的局部邻域内，说明局部精修能够在不明显破坏原候选结构身份的前提下，找到略优的候选点。

因此，图 6-7 和表 6-2 的意义不在于证明局部精修已经完成最终物理设计，而在于说明预测驱动流程能够形成稳定的候选推进链条：预测器负责筛出高分 seed，局部精修负责在 seed 邻域内寻找更优或更稳健的候选，后续真实验证负责判断这些候选是否真正具有物理带隙增益。
```

- `canonical cases` → `典型案例`

## 八、最终建议

如果你现在不想再插入额外 COMSOL 模态图，最稳妥的改法是：

1. 将 `6.4 典型案例与带边模态机制分析` 改为 `6.4 典型案例的局部精修与候选质量分析`。
2. 删除或后移 `ep17 witness case` 这段，把它放到 6.6 或附录中，除非同步插入频散/模态图。
3. 6.4 中不要提前说“真实设计能力已经验证”，改为“候选具有进入真实验证的价值”。
4. 把真正的 COMSOL 验证结论集中放到 6.7，把机制稳定性集中放到 6.8。

这样第六章的证据链会更清楚：6.4 讲候选质量，6.6 讲局部场/形状机制，6.7 讲真实验证，6.8 讲局部鲁棒性。
